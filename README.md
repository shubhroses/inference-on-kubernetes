# inference-on-kubernetes

An inference-style HTTP API that will be run on Kubernetes the way a production service is run: a Helm chart, Prometheus error-budget alerts, a Grafana dashboard and KEDA autoscaling on queue depth, with every operational claim backed by a test that CI executes on a kind cluster.

The "model" is a stand-in that holds a slot for a configurable time and returns a small JSON result; there is no real model and no GPU here.

Under construction: so far there is the service (`app/`) with its unit tests, its container image (`Dockerfile`), and a Helm chart (`chart/`) that brings a ServiceMonitor, a Grafana dashboard, a PodDisruptionBudget and alert rules with it. The rules hold the service to a 99% objective, with a page when the error budget burns fast and a ticket when it burns slowly, and add a latency alert and a saturation alert; `promtool` unit tests (`tests/rules/`) work out when those alerts fire with their real windows and check it without a cluster. GitHub Actions installs the chart on a kind cluster next to Prometheus and Grafana and runs the end-to-end tests in `e2e/`: a smoke test, a check that Prometheus scrapes every pod, a check that every panel of the dashboard has data to show, and two tests that put load on the service from inside the cluster (`loadgen/`) and assert that not one request fails while a rolling update replaces every pod, or while the node that holds every pod is drained. An end-to-end test of the alerts, autoscaling and the full README are still to come.
